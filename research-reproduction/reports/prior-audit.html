1. Original method and scope

The study forecasts HTTP demand using Prophet seasonality followed by LSTM residual prediction. Its MAPE architecture collects metrics with Prometheus, forecasts workload, converts workload to replica demand and executes Kubernetes scaling. The Kubernetes components include Ingress, Service, ReplicaSet, pods, scheduler and API server. Tables 4 and 5 report forecasting errors and prediction time; they do not establish latency SLO compliance, cloud cost savings or a live cluster comparison. Sections 5 and 6 acknowledge further Kubernetes/KEDA integration work, prediction latency, anomalies and vertical scaling.

The source implementation fits Prophet to the chronological training partition, predicts its trend/seasonality for training and test timestamps, computes residuals r[t] = y[t] - Prophet[t], then trains a neural model on pairs r[i] → r[i+1]. Conceptually the hybrid forecast adds the predicted residual to Prophet's forecast for the same target timestamp. The released final combination does not respect that target alignment; see section 5.

These are univariate request-count time series derived from HTTP logs. They are not multimodal data. NASA is evaluated in requests per minute; WorldCup98 metrics use min–max normalized counts. Cloud hardware, provider, node types, CPU/GPU, RAM, operating system and original cluster/tool versions are not specified sufficiently to reconstruct a historical environment.

Paper equation 7 uses forecast workload divided by per-pod rated workload. Equations 8 and 9 both print a less-than condition, although one is labelled scale-up. Treat this as an apparent specification error: scale-up logically requires desired count greater than current count. Do not silently treat the repaired condition as the printed baseline.

The split is by stored rows, not a complete calendar grid: train_test_split(test_size=0.3, shuffle=False, random_state=42). The LSTM pairs are created before a second split. Its validation partition is the final 20% of neural training pairs; fit otherwise leaves Keras defaults, including training shuffle, unchanged. A gap in the CSV means a one-row step can span more than one minute.

Source-verified: Data Processor.ipynb parses log timestamps, floors them to minutes and counts all parsed requests; it does not filter by HTTP method/status or augment data. It groups only observed minutes and never reindexes to insert empty minutes. NASA's timezone offset is ignored by parse_line, leaving local -0400 wall-clock times as naive datetimes. The inspected official WorldCup recreate.c uses gmtime and prints +0000; the notebook strips the timezone and retains those UTC wall-clock values. Do not shift either CSV to Asia/Karachi.

The paper describes zero replacement and no-traffic gaps; the released training cells instead use forward fill on existing training values, and the CSVs have no zero-count rows. Forward fill cannot insert missing timestamps. For the initial code reproduction, use the released CSVs as-is. A zero-filled calendar-grid experiment is a separately labelled deviation.

NASA residuals are scaled to [0,1] using extrema from the full residual series, including test observations. WorldCup raw counts are scaled on the entire dataset as (count - 1) / 229425; its residuals are not separately min–max scaled. These are code facts, not recommended evaluation practices.

5. Evaluation errors and reproducibility barriers

  1. Residual alignment: NASA cells 29–31 and FIFA cells 29–31 construct input r[i] and target r[i+1]. Both cell 52 blocks assign predictions starting at row zero rather than row one. The final score therefore compares Prophet[i] + predicted r[i+1] against y[i], although the prediction used actual r[i]. This is not a correctly aligned next-minute forecast. Preserve it for the first code reproduction; repair only in a distinct baseline-validation variant.
  2. Observed truth fallback: cell 52 fills the final unpredicted row with its actual residual. The resulting last hybrid prediction equals the observation exactly. A corrected evaluation must exclude unavailable targets or forecast them; it must not substitute truth.
  3. Test-informed scaling: NASA cell 28 fits the residual scaler to all rows; FIFA cell 10 fits raw-count normalization to all rows. Training-only scaling is a later correction, not the unmodified release.
  4. Evaluation regime: test residual windows use observed test values. This can support a rolling one-step evaluation only with correctly aligned timestamps and availability. It is not a recursive 30% holdout forecast issued once at the training cutoff.
  5. Training disagreement: paper 50 epochs vs code 20; FIFA flat vs printed linear; auxiliary hybrids do not use the same early-stop/validation/seed policy.
  6. Missing table comparators: no released ARIMA order/selection/refit schedule, one/five-step scripts, standalone LSTM script, or standalone Bi-LSTM one/five-step scripts. Whether five-step metrics score the fifth horizon only or pool horizons is not specified sufficiently. Do not invent these settings and label results exact reproductions.
  7. Timing: main notebooks time batch Prophet test prediction and batch LSTM test prediction using time.time, then add them. They exclude training and most transformation/merge work. This is total held-out batch inference time, not one online control cycle. Hardware, warm-up and repeated timing methodology are missing; millisecond equality is not a reasonable reproducibility requirement.
  8. Run artifacts: no executed outputs in the inspected notebooks, no complete historical package lock, and no comparator run logs. Checkpoints alone do not establish which training run produced every printed value.

9. KEDA implementation and sample app

Source-verified current scaler behavior: loads the NASA Prophet and LSTM checkpoints at startup; fits a hard-coded residual MinMaxScaler on [-118,284]; forecasts Prophet at datetime.now() + 1 minute; subtracts that future forecast from the current Prometheus value; predicts an LSTM residual from this scalar; adds it to the future Prophet forecast. This differs from subtracting Prophet's current-time estimate before forecasting the next residual. The model was trained on 1995 dates and is now queried at current dates, so extrapolation and date/domain transfer must be investigated.

The gRPC server listens on 50051; Flask API/UI on 5000; SQLite stores timestamp, current_value, predicted_value and pod_count in metrics.db. IsActive always returns true; StreamIsActive yields continuously. GetMetricSpec exposes custom_metric with target 1. GetMetrics reads metadata, queries Prometheus, applies scaleFactor, forecasts, replaces low-load forecasts with observed demand below activationValue and returns forecast/podLimit as both truncated integer and floating metric. KEDA/HPA handles final replica reconciliation; the server does not directly call Kubernetes to scale pods.

It selects FIFA 1998-07-07 09:51–16:31, rescales that slice independently, loads the saved FIFA models and repeats the alignment/fill behavior.
